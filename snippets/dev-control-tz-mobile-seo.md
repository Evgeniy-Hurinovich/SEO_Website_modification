## Часть B — Основная новая задача: A4 Canonical (P0)

### B1. Проблема
Live HTML (проверено 11.08 и 20.08) на `/`, услугах, контактах и др.:
- **нет** `<link rel="canonical" href="https://...">`
- есть только `og:url`

Риск: дубли с query-параметрами (`?utm_`, фильтры) размывают вес страниц в Google/Яндекс.

### B2. Требование
На **каждой публичной** странице в `<head>` выводить:

```html
<link rel="canonical" href="https://a2c.by/точный-путь/" />
```

Правила:
1. Всегда **https://a2c.by** (не http, не www — если www редиректит на без www, canonical = финальный хост).
2. Canonical = **канонический ЧПУ** страницы (как в адресной строке без мусорных GET).
3. Согласовать со trailing slash сайта (сейчас URL вида `/services/dwh/`).
4. **Не** ставить canonical на noindex-демо (`/product/`, `/landings/` — они уже закрыты).
5. Типы страниц минимум:
   - главная `/`
   - услуги (разделы + детальные) — IB 42
   - проекты — IB 41
   - новости — IB 38
   - `/contacts/`, `/company/`, отзывы и др. публичные разделы

### B3. Где искать на сервере

```bash
# где уже есть og:url / SEO head
grep -r "og:url\|canonical\|SetPageProperty" /bitrix/templates/aspro-allcorp3/ | head -50

# настройки SEO Aspro / модуль
# Админка: Аспро → настройки SEO / «Индексация» / bitrix:main.include в header
```

Типичные точки Aspro Allcorp3:
- `header.php` / `page_blocks/header_*.php`
- компоненты `bitrix:news` (services / projects / news) — `section.php`, `detail.php`
- SEO-модуль Aspro Smart SEO (если используется для meta)

Предпочтительный способ: **один** механизм шаблона/модуля, а не ручной canonical на каждой странице.

### B4. Проверка после деплоя
1. Сброс кеша: `/bitrix/admin/cache.php?lang=ru` (+ композит при необходимости).
2. View-source для URL:
   - https://a2c.by/
   - https://a2c.by/services/dwh/
   - https://a2c.by/services/bi/
   - https://a2c.by/contacts/
   - 1 новость, 1 проект  
   → везде есть `rel="canonical"` на правильный HTTPS URL.
3. Открыть URL с `?utm_source=test` → canonical **без** utm (на чистый URL).
4. Сообщить список изменённых файлов.

## Часть C — Серверная часть в зоне разработчика (после/параллельно хостеру)

### C1. MySQL isolation (хостер global не даёт)
В `dbconn.php` или init `.settings.php` на сессию:

```sql
SET SESSION transaction_isolation = 'READ-COMMITTED'
```

(или актуальный синтаксис для версии MySQL на хостинге).

### C2. Redis как кеш Битрикс
Только если хостер выдал **host:port** (и пароль при необходимости):
1. Переключить хранилище кеша Битрикс с файлов на Redis (админка Производительность / `.settings.php`).
2. Проверить гостевую выдачу и админку.
3. Не включать «вслепую», если Redis-сервиса нет (один PHP-модуль ≠ сервис).

### C3. Не ваша зона (хостер Олег)
- `opcache.max_accelerated_files` ≥ 100000 (сейчас 10000, красный в Perfmon).
- Подтверждение Redis host:port.
