# E1 — ТЗ на доработку /services/dwh/

Дата: 11.08.2026  
URL: https://a2c.by/services/dwh/  
Раздел инфоблока услуг (Aspro).

## Что уже хорошо

- Title: «Корпоративные хранилища данных (DWH) — A2 Consulting»
- Description коммерческий (DWH / Lakehouse / аудит / ETL)
- H1: «Корпоративные хранилища данных»
- Есть карточки дочерних услуг (внедрение, Big Data, аудит, миграция, онлайн-аналитика, сопровождение)
- Service JSON-LD (D2) на месте
- Есть длинный текст после списка (H2 + блоки выгод)
- Много ссылок на проекты

## Пробелы (что усиливаем в E1)

1. **Мало иерархии H2/H3** — по сути один H2 внизу; нет явных блоков «Кому подходит», «Этапы», «FAQ», «Кейсы».
2. **Нет отдельного FAQ-блока** под поисковые вопросы (PAA): что такое КХД, отличие от Data Lake, сроки, стоимость-ориентир, Lakehouse.
3. **Кейсы** — ссылки есть, но нет видимого блока «Реализованные проекты по DWH» с 2–3 анкорами на релевантные `/projects/...`.
4. **CTA** — общие кнопки сайта есть; на посадочной полезен явный оффер в конце текста («Обсудить архитектуру DWH» → форма/контакты).
5. **Текст сверху (UF_TOP_SEO)** — похоже пуст; короткий лид над карточками усилит первый экран.

## План работ (без правки шаблона PHP)

Делается в админке раздела «Корпоративные хранилища данных»:

### A. Короткий лид над карточками (поле верхнего SEO-текста / UF_TOP_SEO)
2–3 предложения: для кого DWH, какой результат, чем A2 отличается. Без воды.

### B. Доработать нижний текст раздела (DESCRIPTION)
Структура:

1. H2: Построение корпоративных хранилищ данных (КХД) — уже есть, оставить/чуть уточнить  
2. H3: Кому подходит  
3. H3: Что входит в работы  
4. H3: Этапы внедрения  
5. H2: Частые вопросы (FAQ) — 5–6 Q&A  
6. H2: Примеры проектов — 2–3 ссылки на кейсы  
7. Абзац-CTA

### C. Перелинковка
С дочерних услуг и 2–3 кейсов — анкоры «корпоративное хранилище данных», «внедрение DWH» обратно на `/services/dwh/`.

### D. (Опционально позже) FAQPage JSON-LD
После появления FAQ в HTML — отдельный маленький include, как D2/D3.
